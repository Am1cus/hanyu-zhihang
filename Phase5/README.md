# 模型之外：规划、能量与预警研究工具

2026-09-13。复用现有系统，V3 权重保持冻结。本目录是离线软件基础，不接飞控，不向网页填充虚构航程或安全状态。所有 `examples/` 数据都是明确命名的合成软件用例，不是 AirSim 新架次或实测成果。

## 已实现与运行

从仓库根目录执行，不需要新增第三方依赖：

```sh
.venv/bin/python -m Phase5.planning Phase5/examples/grid.json --objective distance
.venv/bin/python -m Phase5.planning Phase5/examples/grid.json --objective energy

.venv/bin/python -m unittest tests.test_phase5 -v
```

## 规划与预算口径

栅格坐标为 `[x,y]`，`energy_wh_per_m[y][x]` 是进入该格的单位距离代价；边代价为该值乘 `cell_size_m`，必须正且完整提供。启发式为曼哈顿距离乘最小单位代价，因此与优化目标同单位。地图无对角移动，不能穿墙角；起终点在障碍内返回不可达。更新障碍后可重新调用 `plan`，这属于离线重新求解，尚非机载动态执行闭环。

当前代价表是输入场景假设，未由 V3 输出：V3 使用过去30秒，不能直接给任意未飞路线打分。单位能耗表可能导致去返程代价不同，所以 CLI 会重新计算返程，不直接乘二。`budget_sufficient` 仅表示输入预算算术满足约束，不表示真实飞行安全或“建议起飞”。输入 Wh 不能从 Ah 直接冒充，缺少任一去返程路线/代价/储备/可用能量时输出不可用。

40个固定随机地图的 A* 结果与独立 Dijkstra 对照通过，是算法正确性检查，不是申报50组极端风力节能试验。示例不同路线的预测代价差也不是实际节能率；以后需独立积分实际执行能耗再评价。

## 能量与低温部分

`integrate_discharge(samples, max_gap_s)` 接收同一 `run_id` 的 `t_s, voltage_v, current_a`。正电流表示放电。输出仅为首末采样点之间的已消耗 Wh/Ah，`remaining_usable_wh` 始终为空。

输入应明确是原始点采样还是秒均值。秒均值电压×秒均值电流不等于秒内平均功率；将桶均值当点采样积分只能算近似，不能写成独立测得的能量真值。实际校准应使用原始同步电压、电流和真实 dt，并记录电池/传感器版本、误差、截止条件。当前没有新增温度经验系数，也未把恒定容量公式当作真实低温机理。

## 风险评价口径

输入一个或多个架次的列表，字段为 `run_id, t_s, voltage_v, risk`。`risk` 是当时发出的布尔预测，未知必须为 `null`；`voltage_v` 允许缺失。阈值和预测时域由调用者明确提供，时域必须是采样步长的整数倍。

标签观察区间是 `(t,t+H]`，要求连续完整的后续电压；不跨断流、缺测或架次。已低于阈值的当前点单列 active，不当成提前预测。首次从高于阈值转为低于或等于阈值定义一个事件；暂未加去抖，所以反复跨阈值会形成多个事件。事件前没有完整 H 秒观察时单列为观察不足；段首已经低压也单列观察不足。

事件提前量取 `[event-H,event)` 内最早的、当时尚未低压的真实预警时间。再次跨阈值时只接受上一次低压恢复后的预警，避免一条早期预警重复命中多个事件。事件召回分母是有完整前史的阈值事件；预测全缺失仍算事件漏报，不能靠弃权抬高召回。逐点召回只在有预测的标签上计算，必须同时报告 `prediction_coverage` 和 `abstained`。逐点精确率不是事件精确率；重叠时间点不是独立样本。无事件时事件召回为 `null`，不记100%。

本模块是后验评估器，未来电压只用于标签与评价，不能作为在线风险预测输入。当前网页的SOC/温度/风速阈值预警保留原含义，并没有因增加评估器就升级成提前预警。

## 通信接入约定

候选主题：`cold-aviation/v1/{droneCode}/runs/{runId}/telemetry`。离线校验器要求外部传入已注册运行信息，不根据消息自行创建无人机或实验；主题、载荷、注册信息三方身份必须一致。输入为完成秒桶右边界时间，不补传感器零值。

成功只表示信封合法，不表示全部传感器可用于推理。示例故意含缺失风字段，校验后原样保留。后续桥接器应将其交给现有 `/api/telemetry`，由后台持久化并给出模型不可用原因。去重、冲突和乱序以现有后台 `(runId,sampleSeq)` 及内容指纹为准，不能在桥接层将所有重复包都当成功。

实际接入前需补：固定客户端身份及主题权限；明确应用持久化确认与重试状态；有界持久队列和重启恢复；保持同机顺序；两台设备的交叉消息、重复、冲突、断线、超时和恢复用例。本轮没有连接 MQTT broker，也未宣称通信链路验收完成。
