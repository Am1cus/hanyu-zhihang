# 寒域智航前端重构计划

2026 年 11 月 18 日制定。正式前端采用冰川蓝。离线设计稿可查看普通风、强风和低电量示例。[冰川蓝设计稿](前端重构线框稿_20261118.html)

## 1. 打开软件，先做哪件事

首页直接回答「给定温度、电量和风速，预计还能飞多久」。第二个问题是「示例路线能否往返，回来时还剩多少电」。想观察无人机如何选择巡看点，或想找回一次运行的人，各有独立入口。

| 一级入口 | 第一眼看到什么 | 用户接下来能做什么 |
| --- | --- | --- |
| **续航与路线**（首页） | 三个输入，留足储备还能飞多久，示例往返是否够电 | 改条件重新预测，查看路线为什么省电 |
| **巡看仿真** | 准备时看场景和起飞预览，运行时看位置、下一站和原因 | 开始、暂停或继续这次巡看，按需改变环境 |
| **运行记录** | 最近的巡看及结果，按创建顺序从新到旧 | 打开旧记录、导出、按原配置从头复演，继续向前翻页 |

三个入口共用标题栏和当前页标记。续航输入与巡看配置分别保留。续航页用 AirSim 参考机型，巡看用 P42A 参考电池和自己的储备规则；切页时沿用各自最近的条件。运行记录只收录巡看。

## 2. 现有页面的具体取舍

我在 Mac 上用 Playwright 操作了现有页面，并依据 ui-ux-pro-max 的信息层级、数值比较、窄屏布局和非颜色提示原则作出以下选择。这里的观察来自界面走查。

| 现有内容与问题 | 重构决定 |
| --- | --- |
| 巡看首页五个导航项中，四个跳转到同一长页；能直接输入天气估时的入口排在最后。 | 改成上面的三个一级入口。任务配置、地图和时间线放回巡看页内部。 |
| 续航页的两个蓝色大数字同样醒目，写成小数分钟。375 × 812 窗口中第一个时间约在页面向下 855 像素处；往返结论约在 2005 像素处。1440 × 900 窗口的往返结论也在约 1287 像素处。 | 主数用「保留 20% 后可飞 2 分 07 秒」，旁边给出「预计至 0% 共 2 分 49 秒」。把往返结论放在地图前；两种尺寸都以首屏可读为排版目标。 |
| A* 的两张卡重复五组指标，图上多条线覆盖。默认例的「低于储备」容易被读成「飞不回来」。 | 首先用一句话交代往返和到站电量。详情用一张地图、一个路线切换和一张对照表。 |
| 「初始剩余Ah」实际选择的是百分比；「积分耗能」「实际剩余扣除固定储备」很难扫读。 | 分别改为「起始电量（%）」「已耗能量（Wh）」「扣除储备后可用（Wh）」。后两项按使用场景放入巡看详情。 |
| 宣传语「每一程，都心中有数」、大写英文副标题、重复的模型说明、酷似按钮的 01／02／03 状态条占据首屏。预览时还出现一排禁用操作。 | 去掉宣传语、重复标识和假按钮。用场景名、状态文字和当下可用的操作占据这些位置。「演示模式」退出主界面，90 秒讲解移到已有使用文档。 |
| 首页同时陈列电流、功率、容量、算法细节；历史藏在「结果复查」下拉框内。 | 电流、功率、容量放进「计算依据」，训练信息和版本只在此出现。历史独立成页；旧版研究图、冻结实验、算法跑分继续从技术档案查阅。 |

## 3. 续航与路线如何工作

**输入和主结果。** 桌面左边输入、右边读结果，窄屏从上到下排。三个常用输入为气温（℃）、当前电量（%）、风速（m/s）。保留一个主按钮「计算续航」。默认条件示例打开即有结果，时间由原始分钟值统一四舍五入到秒。地速、标称容量和储备比例收入「更多条件」，收起时仍显示当前储备、参考容量和地速。超出标定范围时，在结果旁点名具体输入。模型来源、额定工况和误差依据可以展开。

**往返结论。** 以选中的路线和同一次提交的原始数值判断，取整只用于显示。首屏给文字、到站剩余电量和储备线。详情给地图和差异。

| 条件（按顺序判断） | 呈现给用户的结论 |
| --- | --- |
| 去程或返程没有路径 | 「无可行往返路线」，指出哪一段不通，到站电量留空。 |
| 往返路径存在，预计耗电超过当前可用电荷 | 「预计电量不足以完成往返」。即使接口把剩余电量截为 0%，也不写成已到站。 |
| 电量足以往返，但留不够设定储备 | 「预计能返回，到站剩 18.5%，低于 20% 储备」。 |
| 满足设定储备 | 「预计能返回并留足储备」，同时给出到站电量。 |

**地图和 A\* 对比。** 默认选「省电路线」，可切到「最短路线」。同一张图上标出基地、目标、障碍、当前路线的去返方向；去程实线、返程虚线，完全重合的去返段用双向标记。两方案去、返坐标逐段一致时写「两种方案走同一路线」。只有耗电相同则只报告耗电持平。对照表按距离、往返时间、耗电（mAh）、到站电量对齐，小屏保留指标名和两列数值。优先解释取舍，例如强风样例的省电路线多走 40 米、多用 20 秒，比最短路线少用约 30 mAh（3.9%）。均匀风下的续航估计与沿途风场下的路线用时各自标明条件。

**修改与等待。** 用户提交后，续航和路线同时请求，各自就绪就各自显示。修改未提交的输入时，旧结果保留对应的条件摘要并标「条件已改，待计算」。只显示当前这次提交的数据；某一项失败就在该处提供重试。正常更新后不长期占一行提示「已更新」。

## 4. 巡看与历史如何工作

| 巡看状态 | 默认展示与操作 |
| --- | --- |
| 准备 | 场景、可修改的起始条件、地图预览和「开始巡看」。任务选择算法、预算模式、播放速度等放进「仿真设置」。 |
| 执行中 | 地图标出当前位置和下一站，旁边一句话解释选择原因。露出已完成点数、仿真剩余能量和「暂停」。在「改变环境」中加入禁入区或改变风场；「结束本次」放进更多操作。 |
| 暂停 | 原位显示「已暂停」和「继续巡看」，保留地图、进度和原因。已排队的变化写明在下一仿真步生效。 |
| 结束或归档 | 区分「全部完成并返回」「部分完成并返回」「拒绝起飞」「执行失败」「信息不足」和「用户取消」。保留失败原因、是否实际返回和完成点数。可看详情、导出或从头复演。 |

任务清单、最近决策、完整时间线和储备明细按需展开；进入历史详情的人可以看全。点击顶栏不会创建或恢复运行。打开记录先读取其状态；同一进程中仍可继续的暂停任务才显示「继续」。从头复演会创建新记录。若这一操作会暂停另一条正在执行的任务，操作前写明影响。

历史页首批 50 条，「显示更早记录」沿现有游标继续，末页收起按钮。每行显示场景或条件、策略、完成数、运行结果和仿真时长。当前列表接口没有返回创建时间，界面只说「从新到旧」。点开单条后才取明细或导出；空列表直接给「开始第一次巡看」入口。旧进程的记录标「已归档」，同时保留它本来的运行结果，避免把已落盘的暂停状态误当作可继续。

## 5. 版式与实现顺序

保留已认可的三个入口、左右分栏，以及手机上输入、主读数、往返结论的顺序。视觉稿用系统字体排中文和数字，单位缩小，存储中的原始数值继续用于计算。

冰川蓝使用浅冰蓝页面、白色表单与蓝色主按钮。雪岭在续航读数区右侧，可飞时长置于左侧浅色天空上。巡看与历史沿用同一导航和内容底色。

半透明材质用在顶部导航，给滚动中的页面保留位置感。输入、表格及往返结论使用稳定底色。地图采用去程实线、返程虚线和障碍斜纹。低储备、无法返回和留足储备均配有文字及符号。浏览器启用增强对比度时，续航区自动使用纯色背景。这个分工参考了 Apple 对导航材质与内容层的设计原则。[Apple 界面材质指南](https://developer.apple.com/design/human-interface-guidelines/materials)

续航与巡看各自保留本页设置。移动端先显示续航和往返判断，再显示地图及对照。

| 顺序 | 实际改动 | 看到什么算这一段完成 |
| --- | --- | --- |
| 1　统一入口，改续航首页 | 复用 FastAPI 和现有 HTML/CSS/JS。`/` 和 `/endurance` 打开续航；新增 `/simulation`、`/history`。旧首页的 `#main`、`#mission-config`、`#mission-map`、`#model-notes` 由浏览器转到相应巡看位置，`#review` 转到运行记录。 | 从使用说明或旧书签都能进入对应功能。在 1440 × 900 和 375 × 812 下，默认条件的可用时长与往返判断在首屏可读。 |
| 2　重排路线结果 | 复用预测和路线接口，拆开两块结果的加载；增加返程电量分级、地图切换和并排的取舍说明。 | 默认例能看出低于储备，强风例能读出绕行的代价与收益，10% 电量例明确提示往返电量不足。 |
| 3　重排巡看和记录 | 在原执行器上拆分准备、运行、归档视图，记录列表接游标接口。创建与复演沿用已有请求去重。同步本地启动说明；如拆出公共 CSS/JS，将资源后缀纳入 Mac 便携包。 | 能顺着「预览 → 开始 → 暂停 → 继续 → 查看记录」走通，也能从第 51 条起找回旧记录并导出或复演。 |

实现使用已有模型、A* 和历史数据库。启动后的首页可直接输入自己的条件，巡看和历史使用同一套本机服务。[实际操作说明](../competition/v2/TRY_IT.md)
