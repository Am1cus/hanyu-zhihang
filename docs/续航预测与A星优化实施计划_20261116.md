## 要交付的功能

输入温度（℃）、当前电量（%）、风速（m/s），直接得到预计剩余飞行分钟数；同时显示保留 20% 电量后可用的分钟数。通过网页、Python 函数和 HTTP 接口调用。路径规划使用同一个耗电模型，给出往返路线、预计耗电、耗时和当前电量是否足够。

本次由开发者直接确定实现方式并完成，不等待用户选择。使用当前 Mac 和 Python 环境。

## 1. 训练并交付直接续航模型

- 数据使用本地 `Phase4/processed/airsim_capacity_dataset.csv`：35 个仿真架次、1,702 条记录；原文件保持不变。
- 当前标量输入没有时序上下文，采用可解释的混合模型：温度—满电可用容量拟合 + 非负耗电回归 + 电量守恒换算。训练得到的系数保存为独立 JSON，推理无需 PyTorch。
- 用当前容量 / SOC 得到各架次温度下的容量；用电流、风速和运动速度拟合耗电率。按完整架次划分开发与保留数据，不将相邻窗口随机拆散。
- 默认机型沿用这些 AirSim 数据对应的电池和负载；默认平飞地速 2 m/s，默认预留电量 20%。这些默认值在结果中可见，允许在高级参数中调整。
- 输出预计飞至 0% 的时间与飞至预留电量的时间。低于预留电量时后者为 0，前者仍按实际电量计算。
- 数据只覆盖高 SOC 和短航段，续航由耗电模型外推，不生成伪造的“真实耗尽标签”。训练范围以外的正常输入仍给出结果，并在结果中标记外推。
- 温度容量曲线在室温以上保持上限，避免无依据地预测温度越高容量无限增加。容量和耗电不混用 v2 的另一套 4S1P 参考参数。

## 2. 实现能量感知的优化 A*

- 新增 `competition/endurance/pathfinding.py`，复用每张地图的有向边，缓存方向与风场对应的速度及功率。
- 使用四方向最低边代价构造更紧的启发函数，同代价时优先更接近目标的结点；保持最优路径，不用加权启发函数牺牲最优性。
- 同一上下文支持多个端点查询并缓存重复结果；记录构图时间和查询时间，避免将缓存命中冒充单次算法提速。
- 默认按指定地速飞行，受最大空速约束；大逆风/侧风导致无法保持速度时降低地速，不可飞的边不参与搜索。
- 同一个续航模型给各边计算电流与电量消耗；提供最短距离与最小耗电路线对照，分别计算去程、返程及其总预算。
- 旧冻结执行器和旧路径文件保持原版本，旧运行仍能复演；新功能在当前服务中可直接使用。

## 3. 接入当前软件

- 新增 `/endurance` 网页：三个主要输入、一键预测、分钟数和往返地图；高级参数收起显示。
- 新增 `/api/v2/endurance/model`、`/api/v2/endurance/predict`、`/api/v2/endurance/route`，保留原接口；同步 OpenAPI 版本。
- 提供 `python -m competition.endurance ...` 命令行入口，模型文件随源码交付，不要求用户重新训练。
- 默认页面增加续航预测入口，不改写旧实验结果。

## 4. 完成交付所需的检查与说明

- 检查时间计算、SOC/温度/风速变化趋势、耗电预测的保留架次误差；这些误差仅描述所预测的电流/短时耗电，不冒充全航程分钟误差。
- 优化 A* 与独立 Dijkstra 对照最优代价，记录重复查询及含构图的性能变化。
- 实际调用 HTTP 和网页完成三输入预测、往返规划，再运行受影响的 v2 回归。
- 保存训练脚本、独立模型文件、原始结果、简短使用说明和真实运行示例。不启动新的实测、Windows、访谈或答辩工作。

耗电守恒换算参考 [PX4 BatteryStatusV0](https://docs.px4.io/main/en/msg_docs/BatteryStatusV0)：剩余时间以剩余电量及平均负载估计。本项目增加温度容量与风速负载模型；该参考不代表 PX4 为本项目参数或精度背书。
