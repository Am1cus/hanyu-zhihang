# 后端审查与修复记录

2026-11-05。审查范围为 v2 HTTP 输入、SQLite 快照和操作记录、创建与复演的请求去重、后台保存、重启和导出。审查同时阅读了现有 HTTP、运行器及旧版存储检查。复现使用临时数据库和 SQLite 故障注入。

## 确认的问题

| 问题 | 修复前的复现 | 修复方式 |
|---|---|---|
| 非法数字的错误响应失败 | 提交 NaN 或溢出为无限大的 speedup，原校验错误带上该数字，JSON 响应编码失败，最终返回 500 | 编码校验错误时把非有限数值转为 null，返回 422，保留出错字段 |
| 恢复运行违反单任务规则 | 创建 A，再创建 B，随后恢复 A，两个运行同时处于 RUNNING | 恢复 A 时同时暂停 B，记录 resume_demo 原因 |
| 保存失败后出现部分生效 | 注入暂停旧运行的写入故障，新运行和请求编号已经保存，内存未登记新运行。原 key 重试却得到归档记录。注入控制保存失败时，导出显示 RUNNING，数据库仍为 PAUSED | 创建、复演、恢复和相关暂停记录一起提交。控制与事件先修改副本，数据库提交成功后才更新内存 |
| 后台检查点故障让执行停止 | 注入一次 SQLite 检查点错误，解除故障后时间仍停在 10 秒，后台任务已退出 | 捕获 SQLite 错误并保留待保存的运行，后续检查点重试，包含已经到终态的运行。首次故障写入日志 |
| 同一应用实例重新启动时误留活跃记录 | TestClient 两次进入同一应用生命周期，旧运行仍返回 runtime_available=true | 关闭生命周期时清理内存运行表，并在 finally 中关闭数据库，重新启动从已保存档案读取 |

SQLite 接口读写失败现在返回 HTTP 503 和中文提示。创建与复演仍可使用原 Idempotency-Key 重试。手动事件与普通控制沿用原有请求语义，收到回执不明时先查运行记录。[接口交接](BACKEND_HANDOFF.md)

## 修改范围

- api.py 负责错误响应、内存副本、单运行切换和后台保存重试。
- core/storage.py 增加批量事务，原 save 调用通过同一实现保存单条记录。
- test_http_delivery.py 新增六项回归方法，覆盖五类问题及终态保存重试。已有导出检查改为读取提交后的当前运行对象。
- http-v2.openapi.json 补充 503 响应合同。

后台仍按检查点保存。持续的磁盘故障需要恢复存储环境，故障期间内存里的最新进展尚未可靠落盘。数据库内部结构沿用现有表，旧库缺请求表时仍按原迁移逻辑创建该表。
