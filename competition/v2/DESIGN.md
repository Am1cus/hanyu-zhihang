# D1：任务规格与实验方案

## 一页任务定义

**一句话：**在东北冰雪景区拟定巡检场景中，天气变差、可用能量有限时，帮助操作人员选择更值得完成的巡检点，并给返程留出预算。

**研究问题：**在相同任务、当前观测、参数模型与扰动下，任务子集/顺序选择相较于固定顺序和简单贪心，能否取得更高的任务价值；预留估算误差又会减少多少任务、改变哪些储备违例？这两个问题分开比较。

**最小范围：**一架虚拟无人机、二维地图、固定高度、5—8 个任务点、每点一次定时停留。每个点的价值预先固定，完成停留才计分，经过不计分。基地没有分数。点均为可选择的任务，不暗示法规上允许跳过真实必检点。真实必须完成的任务若被发现，需另写硬约束与无解处理，不能把它降为普通权重。

| 项目 | 当前设计合同 |
|---|---|
| 输入 | 基地、已观测障碍/风、当前地点和时刻、温度、估计剩余 Wh、任务坐标/价值/停留时长、已完成点、储备 Wh、误差设置、来源与版本 |
| 输出 | 下一动作、剩余任务顺序、主动放弃/暂缓点及原因、去程/停留/返程预算、储备、余量、计算时刻、使用的数据版本 |
| 主目标 | 在当前模型和预算内最大化所选任务的价值之和；价值相同时选估计耗能较少的方案，再按任务 ID 固定打破平局 |
| 约束 | 路线可达；每个任务最多计一次；完成停留；单独计算有方向的返程；总需求加储备不超过用于判断的可用能量；不能读取未来事件 |
| 参数 | 初始权重采用 1/3/5 的情境假设，待需求核对；默认储备仍为 23℃参考满电 Wh 的 20%，不是安全标准 |
| 边界 | 低温仍用指定 P42A / 4.2A / 理想 4S1P 参考；不把它称作真机模型、低温实飞或通用安全保证 |

**今天成立的是问题定义和手算逻辑。** 真实景区需求、优先级和实际能耗误差没有因此得到验证。

## 预算写清楚，避免“精确小数就是安全”

令本次观测可用能量为 `E_hat`，剩余行程及停留估计为 `C_hat(route)`，储备为 `R`。航段代价有方向，返程不能复用去程。

- 名义判断：`C_hat(route) + R <= E_hat`。
- 误差预算判断：`(1 + e_cost) × C_hat(route) + R <= (1 - e_available) × E_hat`。
- 基本范围为 `0 <= e_available < 1`、`e_cost >= 0`；今天采用各 0.10 的**设计压力范围**，无实测标定，不是“95%置信度”。正式数值判断容差计划为 1e-7 Wh，只解决浮点误差。
- 两种预算方式各与所有选点策略交叉，防止把更保守的储备效果冒称选点算法收益。储备 `R` 不再额外乘误差因子，避免重复计算。
- 上式只约束声明范围内的当前估计。未来突风、路线封锁、传感缺失或范围外误差可能破坏条件。不得承诺在任意未来变化下都能返回。

执行器先保持 v1 指定电流与电芯曲线；误差研究首先扰动**提供给估算器的观测/功率估计**，不悄悄改变厂家放电合同。实际轨迹的原始 V/I/t 仍用于 Wh 积分，Ah 单独保存。每段另记录估算范围是否覆盖该段执行值。

## 方法与可实施接口

所有策略共用同一条航段规划逻辑和相同观测。当前恒定功率的航段能量代价等价于时间代价；v2 的贡献候选是任务选择、误差取舍和解释记录，不把 A* 换个名字当新算法。

| selector_id | 定义 | 作用 |
|---|---|---|
| fixed_order | 按预定次序做下一个点；下一个不可做即返程 | 复刻 v1 的任务规则思想，扩展到 5—8 点；不宣称与 v1 二进制完全相同 |
| nearest_feasible | 在满足同一预算的候选中，选当前最短距离的点 | 直观距离贪心基线 |
| value_per_cost | 在可行点中最大化 `点价值 / (去该点+停留+该点返程的估计Wh)` | 保留有竞争力的价值/成本贪心基线；并列时按较低代价、ID |
| subset_dp | 在当前观测下，对未完成任务的子集与顺序求最大价值可行方案 | 待实现的子集动态规划；小规模用独立枚举核对 |

`subset_dp` 只对**一次当前观测下的静态代价表**求精确解，不称为未知未来事件下的全局最优控制。单一能量约束和加性代价下，保存每个 `(visited_mask, last_task)` 的最小代价，再加最后点的返程与储备判可行。若后来加入时间窗、多资源或时间变化代价，必须修改状态，不能沿用精确性主张。

重决策时机：到达任务点并完成停留、已观测到的新事件、运行中的约定观测刷新。只允许传入当前快照，函数输入不含 `scheduled_events`、未来遥测或执行器真值。未来事件由执行器独立持有。任务执行状态与规划结果分开，前端移动位置仅来自后端执行状态。

接口草案（类型与字段是 D1 约定，服务尚未实现）：

```text
decide(observation, task_catalog, selector_id, budget_mode) -> decision
observation: as_of_s, position, known_map_version, known_wind,
             available_wh_estimate, temperature_c, completed_task_ids
decision: action, ordered_task_ids, deferred_tasks, reason_code,
          route_estimate_wh, return_estimate_wh, reserve_wh,
          assessed_available_wh, assessed_demand_wh, margin_wh,

```

## 状态与必须解释的失败

| 情况 | 决策/运行口径 |
|---|---|
| 有可行任务 | CONTINUE；只是当前方案可行，不显示“已完成” |
| 无可行任务且当前位置可返程 | RETURN；仍须执行到基地才记 returned=true |
| 基地出发时无可行任务 | REFUSED；0 点、未起飞，不计一次成功返回 |
| 当前点返程不可达或返程也不够预算 | RETURN_UNREACHABLE / RETURN_BUDGET_INSUFFICIENT；明确失败原因，不传送回基地 |
| 温度超参考范围、代价缺失、当前状态未知 | DATA_UNAVAILABLE；不以 0 Wh 替代缺值，不显示可行 |
| 部分任务后真正到基地 | PARTIAL_RETURNED；列出完成价值、未做点及原因 |
| 全部任务后真正到基地 | COMPLETED_RETURNED |
| 取消、暂停、计算超时 | 分别记录；都不能计作成功返回。计算超时允许有记录的基线回退，回退须使用同一预算，统计单列 |

## 实验规划：分清算法改动与预算改动

**设计状态：**机器可读 `protocol.json` 为本地设计记录；当前没有 v2 正式结果，也不是有外部时间证明的预注册。保留测试地图尚未生成、未封存。

- 开发集：2 张独立地图用于调试，包含今天的教学逻辑但教学例不算地图评测。
- 保留集计划：4 张不同拓扑地图（开阔、绕行通道、分区连接、稀疏障碍），至少覆盖 5 点和 8 点；每张坐标、权重、障碍、事件、种子与版本入清单。
- 基础条件：4 地图 × 3 温度（0、−10、−20℃）× 4 情境（正常、低初始能量、突风、动态障碍）= **48 个基础条件**。
- 误差压力条件：无偏差、声明范围内的联合偏差、范围外联合偏差，共 3 组；48 × 3 = **144 个配对条件**。
- 四种选点策略 × 两种预算 = **8 个策略组合**，计划 **1152 次确定性执行**。这些不是 1152 个真实独立飞行样本。状态拒绝、失败、超时照样保留。
- 无偏差组执行器与估计按各自已声明模型运行，并不意味着估计值与积分值严格相同；误差组只改变观察/估计合同，见 protocol.json。联合偏差结果不单独归因于某一种误差。
- 正式测试前把实际清单、代码版本与哈希写入冻结记录。保留集运行后改算法或调参，保留旧结果、升版本，并将已看过的集标成已使用；需要新的确认集，不能仍称未见测试。

**成对公平性：**同条件的 8 组使用同一地图、任务价值、初始参考状态、预设事件时间与参数。策略看见相同类型和频率的当前观测，位置不同导致路线不同是合法结果。事件按仿真时间触发，不按“某策略快到了”临时触发。人工现场改参数的记录单列为演示，不混入批量结果。

**动态有效性：**预先指定探针路线和事件时刻，检查新障碍是否封住尚未执行的路径、突风是否改变相关航段代价；检查真正绕行、减任务、返程或失败。对某策略没有影响也照实记录。事件仅 `applied=true` 不算已经证明有效避障。v1 的 12 次未改变轨迹的正式动态组保留，不暗换数据。

## 指标与比较规则

| 指标 | 定义与必须同时报告的量 |
|---|---|
| 任务价值 | 完成停留点的权重总和 / 输入任务总权重；同时报告原始得分和点数 |
| 有效任务价值（主指标） | 真正到基地且实际剩余满足同一储备时才保留任务价值；其余记 0，同时公开原始价值与失败，不掩盖途中已完成任务 |
| 返回与储备 | 返回、部分返回、拒绝、失败、取消、超时分别计数；储备违例数和 Wh 缺口，不合并为“成功率” |
| 模型耗能 | V×I×dt/3600 的 Wh 及 Ah；只有同任务集合、同返程约束的对照才解释能耗差，少做任务不能直接称节能 |
| 误差覆盖 | 逐航段预测范围与执行积分对照；越界次数/分母、最大误差，拒绝启动者没有航段时记 N/A |
| 求解质量 | 静态小例与穷举参考的价值/可行性一致性；动态全程不使用未来知情“最优解”作实时策略 |
| 计算开销 | 标明 CPU/系统/版本的墙钟毫秒，图构建与决策分别记录；与仿真时间、20倍播放分开 |

主要比较：固定预算模式比较四种 selector；固定 selector 比较两种预算。先列每条件差异，再汇总中位数、均值、胜/平/负、最差值和各温度/事件分组。不以事后选子集、美化拒绝率或未声明的加权总分制造优势。不对固定合成批次补 p 值或现实安全概率。

正确性门槛是硬要求：静态解与独立枚举一致；无障碍穿越；达到基地后才记返回；预算/积分守恒误差 ≤1e−7 Wh；缺数据明确拒绝；相同输入的确定性结果一致。速度内部目标是在答辩电脑 8 点常见情景决策约 1 秒以内，须实测，不是已达成指标。

不预设节能或得分提升百分比。若精确选择与简单策略相当，要报告哪些场景相当；若保守预算只降低任务量却没有减少声明误差下的违例，就不能主张综合改进。

## 手算例：它检验的是定义，不是效果

S 为基地；普通点 A/B 各 1 分，重要点 C/D 各 5 分，E 为 3 分。位置和有方向的边代价见 fixtures。总可用 11 Wh、储备 2 Wh，各点停留 0.5 Wh。

- C→D 的往返与停留总计 `3+0.5+1+0.5+4=9 Wh`，名义预算恰好可行，10 分。
- 将可用能量按 10% 留误差，剩 9.9 Wh；需求按 10% 上调。C→D 需求加储备为 `9×1.1+2=11.9 Wh`，不再可行。
- 只做 C：`(3+0.5+3)×1.1+2=9.15 Wh`，还余 `9.9−9.15=0.75 Wh`，5 分。
- A 去程 1 Wh、返程 1.2 Wh，加停留共 2.7 Wh。这个方向差异不能省略。
- 简单价值/成本贪心在名义组也能得到 10 分，和精确参考相同。此例不能用于宣称新算法提高多少。
- 若实际代价误差达到 30%，C 计划可能低于储备；范围外失败应显示。这不是实际飞行录制，returned 始终未验证。
