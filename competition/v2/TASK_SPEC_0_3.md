## 一句话定义

**在黑龙江冰雪景区的一趟辅助巡看中，根据当前温度、风和电量，安排先去哪些点、预留多少返程能量，并列清未完成任务。**

拟定用户为景区值班人员和无人机操作者。候选任务限定为可推迟、可重排的补充查看；首版动作是软件中的定时停留。任务价值是开发假设，停留不等于真实拍照、检测成功或安全确认。

## 确定的接口

`DecisionRequest`包含当前时刻与位置、已完成点、已知地图及风、估计可用Wh、温度、5—8个任务、策略、预算参数及参考来源。未来事件仅由执行侧`Scenario`持有。

`Task`新增两个无默认值的必填字段：

```json
{
  "service_level": "optional_supplemental_observation",
  "action_semantics": "simulated_dwell_only"
}
```

`GridMap`新增必填`blocked_cell_meaning="fixed_altitude_2d_exclusion_area"`，表示固定高度二维模型中不可进入的作业区域；地面积雪堵路不能自动解释为无人机航路封锁。模型不判断真实区域的飞行许可。

`DecisionRecord`保存动作、顺序、预算、未选点及原因。`DeferredTask`新增必填`follow_up_state="REQUIRES_OPERATOR_REVIEW"`，表示需处理，不能表示人工已经接单；`COMPLETED`不再是未选点原因，已完成点只来自观测。

后续求解器输出必须通过已实现的`validate_decision_for_request(request, record)`后再接受或导出。它核对请求哈希、时刻、策略、预算模式、目录完整性、基地拒绝条件、储备和预算公式。它不独立证明路径最优、传感状态真实或已执行返回。

合同0.3不自动为旧请求补上“可延期”。0.2源码保存于工作区`output/4C/v2/day11/before/source/`；day2检查证据保持历史状态，0.3结果写入day11。

两图的坐标、数值分值、障碍布局、风、80米网格、5m/s空速、40米高度标注、10秒停留和事件时刻保留0.2数值。变更限于版本、业务名和显式业务限制；来源仍为合成假设。

| 检查ID | 条件 | 本阶段检查目标 |
|---|---|---|
| SC-01 | 五点图，55%剩余Ah，0℃与−20℃ | 可用Wh随参考温度变化，储备不缩小 |
| SC-02 | 五点图，−10℃，10%剩余Ah | 给定去C并返程的预算不足 |
| SC-03 | 八点图，第32秒北通道禁入 | 从同一计划位置去C，路线绕南侧，800米变1600米 |
| SC-04 | 八点图，第32秒双通道禁入 | 到C及C回基地不可达，代价为null |
| SC-05 | 八点图，第32秒东区逆风增强 | 从同一位置去C的估计耗能增加 |

D2历史检查中的SC-03—05为独立条件；当时第32秒位置由事前计划推算，非执行器遥测。上述检查和接口负例为开发验收，不计正式实验或完整运行。
