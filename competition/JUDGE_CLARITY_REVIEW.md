## 主线：先留回程，再做巡检

整场只让评委记住一个问题：**“还有三个点，剩下的能量够不够做完，并回到基地？”**

作品给出的回答是：把巡检、返程、储备分成三笔账；条件改变后重算；下一点预算不足时减少任务、尝试返航；到达基地才计为已返回。这里的“先留回程”是预算规则的通俗表达，不表示软件先飞一次回程，也不承诺真实飞行安全。

开场建议：

> 各位评委好，我们做的是寒域智航。面对东北冰雪景区的拟定巡检任务，它先算回程与储备，再决定下一处还能不能去。今天用软件仿真展示一次“少做两个点，返回基地”的取舍。

项目全称保留在封面副标题。主讲不依次读出“东北冰雪景区无人机巡检任务决策与仿真验证平台”的所有修饰语。A*、电芯型号、恒流条件和模型版本在相应页面出现，但不用它们代替故事开头。

## 90 秒主演示：选择低预算场景，减少现场操作

**建议主方案：**采用已经有冻结档案的“低预算·场景 1 / −20℃ / 能量优先 / 20% 储备 / 20 倍仿真”。主演示聚焦一个自动取舍，不同时塞入正常任务、加障碍、暂停、返航、复演五项操作。障碍绕行用第 10 页的实际档案展示，已有备用视频保留并注明录制版本。

新版入口“看懂低温取舍”载入两温度完整预演，“运行 −20 °C 案例，观察一点后返程”启动低温运行；“加载避障补充情景”是正常场景补充入口。0℃起飞保守预算支持2点、实际执行3/3并返回；−20℃初始支持1点、执行1/3并返回。上界功率预算、曲线积分执行和逐点重算要分开解释，不能将0℃实际3点写成初始预测3点。

已核对本地正式档案 `output/4C/evidence/formal/runs/low_budget-s1-t-20-energy.json`：初始可用 27.1882 Wh，完成 1/3 点，已返回，结束原因 `partial_task_returned`，仿真时长 514.381 秒。在理想 20 倍连续运行下播放部分约为 25.7 秒，实际墙钟还含计算、操作、暂停和渲染，不能因此宣称完成了90秒真人彩排。

**重要的精度边界：**冻结个案完成第一点后，下一点预算差仅−0.00743 Wh。这是参考模型的规则触发，不能包装成真实设备“精准识别7毫瓦时的危险”。主讲展示起飞前27.19对29.68 Wh的明显差额，遇到追问说明近阈值结果受曲线提取、估算器与模型误差影响，后续需校准。

## 最易混淆的词，统一改成可核对的说法

| 当前易混说法或界面关系 | 会引起的误解 | 建议用词与解释 |
|---|---|---|
| “比较两种策略”旁同时放总预算和完成轨迹 | 把完整预演执行结果当作只根据起飞观测的预测 | 分成“整轮初始预算：按当前已知条件估算”和“预演执行结果：本场景已跑完”。完整执行可能遇到预置事件，起飞预算不读取未来事件。 |
| “预算够用” | 以为保证全部三个点、未来风场与真实飞行安全 | 加范围：“整轮任务预算”或“下一点预算”。运行页下一点预算只覆盖下一点驻留、该点返程及储备。 |
| “预算余量”“剩余能量”“储备余量”交替说 | 以为三个数字相同 | 预算余量＝可用−该次估算需求；剩余能量＝参考执行积分后剩余；返航后的储备余量＝剩余−储备。每张卡片保留单位与范围。 |
| “耗能下降所以低温更节能” | 把恒流条件下较低电压造成的Wh下降当成收益 | 同任务起始条件下，低温参考可用能量也下降；先讲可用与需求、任务量的取舍。不同任务量不能直接比较节能。 |
| “暂停了”“任务结束了”“已返航” | 以为停止动画即已返回或完成任务 | 暂停＝暂不推进，可继续；结束任务＝操作员取消，当前可能未返回；已返回＝后端确实到达基地。组员`eb4d87db…`是1/3、未返回、`operator_cancelled`，只能作为取消操作例。 |
| “运行完成”“完成率100%” | 把终态记录数或返回率当作三点完成率 | 固定并列展示“已巡检x/3”和“已返回/未返回”；需要说明运行终态时另写“全部巡检后返回/部分巡检后返回/操作员取消/失败”。 |
| “暂停与复演全程可追溯” | 以为旧导出也含全部控制历史及原记录关联 | 已核验旧导出缺暂停历史与复演来源；本轮新增`execution_audit` schema1记录成功的创建、暂停、恢复、取消和复演来源ID，独立于结果哈希。旧未记录部分仍未知，不修改旧档案补造历史。 |
| “毫秒响应”“20倍实时响应” | 把CPU计算、事件到新决策的仿真间隔和视频播放倍率混为一谈 | 三行分开：计算耗时xx ms；事件→新决策xx仿真秒；演示20倍仿真。CPU快不表示当前位置立即重规划，现有执行在下一地图节点重决策。 |
| “相同配置导出文件完全相同” | 要求UUID、计算耗时和文件哈希也一致 | 表述“确定性执行结果一致”；使用该版本定义的`result_sha256`复核，另列文件SHA用于保存文件完整性，二者用途不同。 |
| “能量A*是原创低温节能算法” | 把已有A*与恒功率×时间当成新的电化学模型 | 口头说“风场下的时间与参考能量代价规划”，界面策略名可保留但附一行解释；贡献讲任务预算、条件响应、执行和档案闭环。 |

组员记录给出的 Windows 个案重规划约4.55 ms和仿真反应1.00 s，只描述该个案；研究简报正式批次的CPU P99约2.45 ms、事件到决策8仿真秒描述另一批次。不要拼成统一“4.55ms内自动返航”的性能结论。复演时CPU耗时变化而确定性轨迹保持一致是正常现象。

## 让作品更容易记住的画面与讲法

1. **一张地图贯穿主讲。**基地与三个点保持位置、编号和颜色。第一点后返程时淡化未访问的点2和点3，保留文字“未巡检”，不要用消失动画暗示已完成。
2. **三笔账固定位置、名字和颜色。**巡检、返程、储备都带文字，返程至少和巡检同等醒目。Wh第一次解释为“能量单位”，后续直接读数；Ah、虚拟组串并联、电压积分留在参数附录。
3. **只用一组关键对照。**同一冻结低预算场景：0℃3/3并返回，−20℃1/3并返回。主讲不再用多个正常场景的细小百分比争取印象分。
4. **数据只保留能支撑结论的精度。**主画面27.19、29.68 Wh足够；CPU耗时、微小阈值差与长UUID放档案或附录。不要让每页口头主句连续读出十几个数字。
5. **把证据层次画出来。**厂家参考数据、软件实验、学生真实操作是三种证据。真实设备验证仍是下一步。已有资料不需要在每一段反复插入长免责声明；在参数页、结果页和完成情况页明确标注即可。
